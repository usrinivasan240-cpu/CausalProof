# CausalProof Limitations

## Causal Inference Limitations

1. **Correlation ≠ Causation.** The analysis engine identifies associations between evidence and outcomes. It does not prove causation. Hypotheses are labelled with calibrated statuses (SUPPORTED, POSSIBLE, UNCERTAIN, INSUFFICIENT_EVIDENCE) to reflect this.

2. **Observational data.** The engine works with observational data, not controlled experiments. Confounding variables may exist that are not captured in the uploaded data.

3. **Selection bias.** The evidence extraction pipeline processes only the data provided. If critical data is missing, the analysis may be incomplete.

4. **Temporal resolution.** The prototype does not perform time-series analysis. Causal timing (which event preceded which) is inferred from data structure, not precise timestamps.

## Data Limitations

1. **CSV-focused evidence extraction.** The rule-based engine extracts detailed evidence primarily from CSV datasets. JSON and text files produce limited evidence. PDF text extraction is not implemented.

2. **Schema recognition.** Domain-specific evidence extraction relies on recognizing column names and file patterns. Unrecognized schemas receive generic numeric summaries only.

3. **No data cleaning.** The engine does not impute missing values, handle outliers, or correct data quality issues beyond flagging them.

4. **Synthetic demo data.** All demonstration numbers are synthetic values generated by a deterministic PRNG. They are not real-world statistics.

## Engine Limitations

1. **Deterministic rules.** The analysis engine uses fixed rules, not learned patterns. It cannot discover novel relationships beyond its programmed logic.

2. **Simple confidence model.** Confidence scores are computed from evidence weights using a bounded exponential function. This is a simplified approximation of epistemic uncertainty.

3. **No statistical tests.** The engine does not compute p-values, confidence intervals, or perform hypothesis testing in the statistical sense.

4. **Fixed failure categories.** The six failure categories (implementation, mechanism, context, design, external, measurement) are predefined and may not cover all possible failure modes.

## Counterfactual Limitations

1. **Deterministic simulation.** Counterfactual scenarios use simple arithmetic rules (e.g., proportional recovery from schedule conflicts). They are not causal models.

2. **Stated assumptions.** Each counterfactual explicitly lists its assumptions. Results are valid only if those assumptions hold.

3. **No prediction.** Counterfactuals are labelled ESTIMATE / SCENARIO — NOT OBSERVED FACT. They should not be used for prediction.

## AI Safety

1. **No fabricated evidence.** The engine never invents evidence. If data is missing, it reports INSUFFICIENT_EVIDENCE.

2. **No hallucinated causality.** Hypotheses use calibrated language. The engine never says "X caused Y" unless the evidence genuinely supports that conclusion.

3. **Contradicting evidence surfaced.** The system displays contradicting evidence rather than hiding it.

4. **User inspection.** All major claims can be traced back to source data through evidence proof cards.
